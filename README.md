# Прогноз продаж — SberHack

Недельный прогноз продаж по складам и товарам на 9 недель. Готовый результат —
[outputs/submission.csv](outputs/submission.csv), обученная модель — в [model/](model/).
Для запуска сервиса переобучение не требуется.

Конкурсный прогноз построен по данным до **26.07.2026 включительно**.
Начала прогнозных недель: **27.07–21.09.2026**; последняя неделя заканчивается 27 сентября.

## Решение и качество

Один LightGBM прогнозирует все пары и горизонты. Модель обучена на `log1p(quantity)`;
после обратного преобразования значения ниже 0.75 обнуляются. Признаки: лаги продаж,
скользящие статистики, сезонность, категории, склад и исторические остатки.
Активный вариант — `log_t0.75`, 400 деревьев и 65 признаков.
Обучение, CLI и API используют общий код из `forecast/`.

Продажи суммируются по всем департаментам, городам и характеристикам.
Дубли остатков суммируются; отрицательные остатки допустимы. Прогноз остатком не
ограничивается. Денежные поля не используются.

По сохранённому отчёту модель выбрана на двух временных окнах и оценена на третьем:
25.05–26.07.2026. Метрики взяты из `reports/comparison.json`.
Во всех столбцах меньше — лучше.

| Прогноз | SMAPE | WAPE, % | RMSE | Bias, % | RMSLE |
|---|---:|---:|---:|---:|---:|
| Последняя неделя | 74.37 | 58.42 | 3.9720 | 120.69 | 0.6173 |
| Среднее за 8 недель | 111.71 | 49.61 | 3.2781 | 65.28 | 0.4873 |
| Предыдущий LightGBM | 64.66 | 47.40 | 3.3456 | 67.58 | 0.4875 |
| Активный LightGBM | 60.64 | 47.09 | 3.3094 | 71.85 | 0.5109 |

У активной модели лучше SMAPE, WAPE и RMSE, чем у предыдущей, но хуже Bias и RMSLE.
Проверка этой копии подтвердила загрузку модели и воспроизведение её CSV без обучения.
Подробности: [валидация](reports/validation.md), [проверка по ТЗ](docs/COMPLIANCE.md).

## Сборка Docker

Нужен Docker с Linux-контейнерами. Проверено на Engine **28.5.1**, платформа
`linux/amd64`. Модель работает на CPU; GPU и NVIDIA Container Toolkit не требуются.
При сборке нужен интернет для установки зависимостей. Во время прогноза сеть не нужна.

```sh
git clone https://github.com/Va-Ya/sberhack-forecast.git
cd sberhack-forecast
docker build -t sberhack-forecast:1.0 .
```

В образ входят код, зависимости и готовая модель. Обучающие CSV и архив данных
исключены через `.dockerignore`. Контейнер работает от пользователя `forecast`.

## Запуск

```sh
docker run --rm --name sberhack-api -p 127.0.0.1:8000:8000 sberhack-forecast:1.0
```

API доступен на `http://127.0.0.1:8000`, OpenAPI — на `/docs`.
GPU-флаги не нужны. Используется один worker: последний прогноз хранится в памяти
процесса. После перезапуска нужно снова загрузить данные.

Запуск без Docker, обучение и автономная проверка описаны в
[docs/HUMAN_GUIDE.md](docs/HUMAN_GUIDE.md).

## API

Команды ниже используют небольшие синтетические CSV из репозитория. В PowerShell
вызывайте `curl.exe` вместо `curl`.

```sh
curl http://127.0.0.1:8000/health
curl -X POST http://127.0.0.1:8000/predict -F "sales=@data/demo_sales.csv" -F "stock=@data/demo_stock.csv" -o forecast.csv
curl "http://127.0.0.1:8000/predict?article=char_article_0" -o article.csv
curl "http://127.0.0.1:8000/predict?warehouse=warehouse_name_0" -o warehouse.csv
curl "http://127.0.0.1:8000/predict?article=char_article_0&warehouse=warehouse_name_0" -o pair.csv
curl "http://127.0.0.1:8000/predict/all?format=csv" -o all.csv
curl "http://127.0.0.1:8000/predict/all?format=json" -o all.json
```

Для своих CSV подставьте в GET товар и склад из загруженных файлов.
`GET /health` проверяет загрузку модели; остальные GET возвращают последний
успешный прогноз. У `/predict` нужен хотя бы один фильтр.

`POST /predict` принимает файлы `sales` и `stock`, каждый с историей не менее
180 календарных дней. Схема — в [docs/HUMAN_GUIDE.md](docs/HUMAN_GUIDE.md#входные-csv).
Ответ: CSV с колонками `week,warehouse_name,article,quantity`, девять недель с
понедельника после недели максимальной даты продаж. Остатки позднее этой даты
исключаются. Конкурсная отсечка применяется при обучении, а API работает с датами
загруженной истории.

Одновременно выполняется один POST. Ошибка запроса сохраняет предыдущий прогноз.
Ошибки возвращаются как `{"detail":"...","code":"..."}`:

| HTTP | Причина |
|---|---|
| 400 | Пустой или нечитаемый CSV, нет фильтра, неверный `format` |
| 422 | Нарушение схемы, неверные даты/числа, отрицательные продажи, короткая история |
| 409 | Прогноз ещё не рассчитан или другой POST выполняется |
| 404 | Запрошенного товара, склада или пары нет |
| 500 | Ошибка расчёта |

## Ограничения

- Официального списка пар нет. Принято полное произведение **11 складов × 799
  товаров × 9 недель = 79 101 строка**. Совпадение со скрытым эталоном не подтверждено.
  CSV пар `warehouse_name,article` можно передать в CLI через `--pairs`; для API —
  положить в `model/allowed_pairs.csv` перед запуском. Переобучение не требуется.
- Фактов за все конкурсные недели нет. Метрики выше относятся к историческому
  окну; место в лидерборде по ним определить нельзя.
- При загрузке только 180 дней годовые признаки недоступны; равенство качества
  полной истории не подтверждено.
- Bias и RMSLE активной модели хуже предыдущей версии. Поддержка экспериментального
  ансамбля есть в коде, но активна сохранённая модель LightGBM; ансамбль не включён.
- Сырые данные, окружение и кэши не входят в Git. Для переобучения нужен отдельный
  `hakaton.zip`. Выпуск `v1.0.0` старше текущих исправлений; используйте ветку `main`.

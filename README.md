# SberHack — прогноз продаж на 9 недель

Цель: недельный прогноз `quantity` для каждой пары склад × товар. Решение использует
общий LightGBM, временную валидацию и единый код признаков для CLI и FastAPI.
Основной прогноз: 27 июля — 21 сентября 2026 года; данные после 26 июля исключены.

## С чего начать

- **Участникам команды:** [понятная инструкция](docs/HUMAN_GUIDE.md).
- **Следующему агенту:** [порядок продолжения](docs/AGENT_GUIDE.md) и
  [готовый текст задания](CONTINUE_PROMPT.md).
- **Готовый результат:** [submission.csv](outputs/submission.csv), переобучение не требуется.
- **Статус и оставшиеся действия:** [HANDOFF.md](HANDOFF.md).

Это самостоятельное решение хакатона. Приложение «Команда» находится в отдельном
репозитории Shelpess/komanda; отсюда для проекта взяты четыре навыка с сохранением
происхождения и лицензии. Исходные большие CSV в Git не включены.

## Запуск в Windows

Нужен Python 3.13. В корне проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m forecast.cli prepare --archive hakaton.zip
.\.venv\Scripts\python.exe -m forecast.cli train --archive hakaton.zip
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 1
```

Выходной файл: `outputs/submission.csv`. Модель, словари категорий, список признаков,
seed, настройки и версии пакетов сохраняются в `model/`. Контрольные суммы данных,
журнал экспериментов и все пять метрик находятся в `reports/`.

Готовый вариант: LightGBM на `log1p(quantity)` с обнулением значений ниже 0.5.
На контрольном окне SMAPE 64.66 против 74.37 у последнего недельного значения,
WAPE 47.40% против 58.42%. Подробности: `reports/validation.md`.

Проверено 25 тестов, точное совпадение CLI/API на 79101 строке реальных данных,
повторная загрузка модели и воспроизведение конкурсного CSV. Фактический запуск
Windows HTTP API проверен отдельно. Docker требует восстановления WSL на текущем
компьютере; сборка и запуск контейнера пока не подтверждены.

`prepare` сохраняет четыре baseline-прогноза; `train` сначала проверяет модели на
двух временных окнах, фиксирует выбор, затем оценивает его на третьем контрольном
окне и переобучает на всей разрешённой истории. Завершённые модели фолдов повторно
используются только при совпадении параметров и контрольной суммы архива.

## Подход

- CSV читаются порциями. Дубликаты остатков суммируются по дате, складу и товару;
  продажи суммируются по департаментам, городам и характеристикам.
- Поддерживаются `article` и `char_article` в остатках. Отрицательный `stock` допустим;
  продажи не ограничиваются остатком. Отсутствующий stock остаётся неизвестным.
- Признаки: 13 недельных лагов, средние/разброс/доля нулей за 2–26 недель, недавние
  продажи, давность спроса, сезонность, категории и агрегаты остатков за 28 дней.
- Неполная неделя имеет отдельные признаки дней и накопленных продаж. Последний
  недельный лаг всегда относится к полной неделе. Обучение включает воскресные и
  пятничные даты среза.
- Категории выбираются только из записей, доступных к дате прогноза. Денежные поля
  не используются. В исходном файле обнаружены три пропуска `sales_sum`; они
  сохраняют смысл неизвестного значения и не превращаются в нулевые продажи.
- Сравниваются последнее значение, средние 4/8 недель, сезонный baseline, LightGBM
  MAE на исходной шкале и MSE на `log1p`. Для каждой модели заранее заданы также
  вариант с порогом 0.5 и смесь 80% модели + 20% среднего за 8 недель.
- Фолды начинаются 19.01, 23.03 и 25.05.2026, каждый длится 9 недель. Третий фолд
  не участвует в выборе. Скор: SMAPE 50%, WAPE 20%, RMSE 15%, |Bias| 10%, RMSLE 5%.
  Локальный ранговый скор сравнивает только наши кандидаты и не предсказывает
  место на конкурсе.

## Допущение о парах — требует подтверждения организаторов

В архиве нет эталонного списка допустимых пар. По согласованному временному правилу
используется полная сетка 11 складов × 799 товаров × 9 недель = **79 101 строка**.
Часть пар отсутствует в истории. Их отсутствие не является основанием исключать
их из submission. Точное совпадение со скрытым эталоном пока не подтверждено.

Если появится CSV `warehouse_name,article`, его можно применить без переобучения:

```powershell
python -m forecast.cli predict --sales sales.csv --stock stock.csv --pairs allowed_pairs.csv --output forecast.csv
```

Для API положите подтверждённый список в `model/allowed_pairs.csv` и перезапустите
сервис. `model/pairs.csv` — справочная сетка обучения, она сама по себе не ограничивает
новые входные данные. Без подтверждённого списка API строит произведение складов и
товаров из двух входных файлов.

## Docker

Нужен Docker Desktop с Linux engine либо Docker Engine на Linux, CPU amd64, GPU не
требуется. Сначала выполните обучение — в образ копируется готовый `model/`.

```powershell
docker build -t sberhack-forecast:1.0 .
docker run --rm --name sberhack-api -p 127.0.0.1:8000:8000 sberhack-forecast:1.0
```

Образ работает от отдельного пользователя. При инференсе используются только
загруженные файлы и локальные артефакты модели; обучение и сетевые загрузки не
выполняются. `.dockerignore` исключает архив и обучающие CSV. Один worker сохраняет
единый кэш последнего прогноза. Для автономной проверки предусмотрен отдельный
smoke-тест с `--network none` и запросами внутри контейнера.

`requirements.txt` содержит зависимости инференса, `constraints.txt` закрепляет
их транзитивные версии. Для обучения `requirements-train.txt` добавляет scikit-learn;
`requirements-dev.txt` дополнительно устанавливает средства тестирования.

Фактический статус проверки текущего компьютера и продолжение при ошибке WSL
описаны в `reports/environment.md`. Наличие Dockerfile само по себе не означает,
что сборка и автономный smoke-тест прошли.

## API

`GET /health` сообщает готовность модели и наличие рассчитанного прогноза.

```bash
curl http://localhost:8000/health
curl -X POST http://localhost:8000/predict -F "sales=@sales.csv" -F "stock=@stock.csv" -o forecast.csv
curl "http://localhost:8000/predict?article=char_article_1" -o article.csv
curl "http://localhost:8000/predict?warehouse=warehouse_name_3" -o warehouse.csv
curl "http://localhost:8000/predict?article=char_article_1&warehouse=warehouse_name_3" -o pair.csv
curl "http://localhost:8000/predict/all?format=csv" -o all.csv
curl "http://localhost:8000/predict/all?format=json" -o all.json
```

В PowerShell используйте `curl.exe`, чтобы избежать alias на Invoke-WebRequest.
Документация OpenAPI доступна на `/docs`.

POST принимает `sales` и `stock` в multipart и возвращает
`week,warehouse_name,article,quantity`. Требуется минимум 180 календарных дней
истории в каждом файле. Первое прогнозное число — понедельник после календарной
недели максимальной даты sales. Например, для 31.07.2026 это 03.08.2026.
Более поздние остатки отбрасываются. В отличие от конкурса, API не применяет
фиксированную отсечку 26.07 к новым входным данным.

GET возвращает последний успешный POST, который хранится в памяти до перезапуска.
Ошибка нового POST не уничтожает прежний прогноз. Одновременно рассчитывается один POST.
Ответы CSV используют фиксированную точность до 8 знаков после запятой.

Ошибки имеют форму `{"detail":"...","code":"..."}`:

| HTTP | Причина |
|---|---|
| 400 | Пустой/нечитаемый CSV, отсутствие фильтра, неподдерживаемый format |
| 422 | Колонки, даты, числовые значения, отрицательные продажи, история <180 дней |
| 409 | Прогноз ещё не рассчитан либо другой POST выполняется |
| 404 | Нет запрошенной пары, склада или товара |
| 500 | Ошибка инференса; прежний кэш сохранён |

## Ограничения и передача

Качество зависит от данных и не гарантирует место в лидерборде. Будущие цены,
скидки и остатки неизвестны и не подставляются из будущего. Годовая история
недоступна при загрузке только 180 дней — соответствующий признак помечается
отсутствующим. Неизвестные категории получают код -1.

Состояние, фактические результаты проверок, текущие процессы и ограничения
фиксируются в `HANDOFF.md` и `reports/`. Перед передачей другому участнику
сохраните всю папку проекта; данные и окружение восстанавливаются отдельно.
Архив решения содержит код, модель, отчёт и CSV, но не исходные датасеты.
Отправку организаторам и уведомление Telegram выполняет команда.

Навыки взяты из Shelpess/komanda, коммит
`c8dfa617a2ef1523c713ba79e88189d93b0f1173`, исходный каталог ECC 2.2.3 (MIT).

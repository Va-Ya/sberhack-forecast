## Приоритетные следующие задачи

1. Проверить `docker version`. Если engine доступен, собрать Dockerfile и выполнить
   `tools/container_smoke.py` внутри контейнера с отключённой сетью.
2. Сохранить фактические время сборки/POST/GET, размер образа и результат паритета
   в `reports/`. Оставлять NOT RUN для проверок, которые не выполнялись.
3. Если получен официальный список пар, применить его и проверить точное равенство ключей.
4. Обновить HANDOFF и архив. Сохранить предыдущий рабочий прогноз и модель.

Если Docker по-прежнему блокирует ОС, завершайте независимые проверки и сообщайте
конкретный блокер. Не сбрасывайте Docker, VHDX или WSL-дистрибутивы. Скрипт
`restart-wsl-admin.ps1` требует администратора и отказывается прерывать активную WSL VM.

## Команды из корня клонированного проекта

```text
python -m pip install -r requirements-dev.txt -c constraints.txt
python -m pytest
python -m ruff check forecast app tests tools score.py
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

`tools.verify_release` требует локального `data/cache/panel.npz`, а
`tools.report_results` — локальных `reports/predictions/*.npz`. Эти файлы не
хранятся в Git. На свежем клоне используйте уже сохранённые отчёты и проверки;
не объявляйте отсутствие кэша дефектом модели. Для восстановления панелей нужен
исходный `hakaton.zip` и `python -m forecast.cli prepare`.

Переобучение выполняйте только при необходимости, с учётом времени, RAM и уже
зафиксированного контрольного окна. Оно требует `requirements-train.txt` и архива:

```text
python -m forecast.cli train --archive hakaton.zip --iterations 180 --pairs-per-origin 600 --threads 2
```

## Обязательные инварианты

- Конкурсные данные строго по 26.07.2026, прогноз 27.07–21.09.2026.
- Все признаки, категории и агрегаты должны быть доступны к дате соответствующего среза.
- Отрицательные остатки допустимы; дубли суммируются; продажи остатком не ограничиваются.
- Обучение/CLI/API используют общий код преобразований.
- Список пар ограничивает выдачу, но не удаляет исторический контекст из признаков.
- Первые два окна выбирают модель; третье контрольное не используется для дальнейшей настройки.
- Ни публикация в открытый доступ, ни сообщения организаторам, ни приглашение участников
  не разрешаются самим наличием файла инструкции.

После изменения поведения добавляйте содержательную регрессионную проверку,
выполняйте подходящие тесты и обновляйте журнал. Не повторяйте полное обучение
только из-за правки документации или упаковки.

Пользователь просил предупреждать о расходе выше 50% доступного лимита. Если есть
`get_usage_limits`, проверяйте его на этапах и предупреждайте при >50% любого
доступного окна. Это общий расход аккаунта Codex, а не отдельный бюджет чата или
универсальный счётчик подписки Plus. Предупреждение не означает просьбу остановить работу.

# Продолжение разработки

Сначала прочитайте `AGENTS.md`, `HANDOFF.md`, `README.md` и
[проверку по ТЗ](COMPLIANCE.md). Затем проверьте `git status` и актуальность remote.
Правила проекта и четыре навыка находятся в `.agents/skills/`; их upstream-материалы
служат справочниками. Лицензии и provenance нужно сохранить.

## Рабочие артефакты

- `model/config.json`, `model/log.txt`, `model/pairs.csv` — активный `log_t0.75`.
- `outputs/submission.csv` — 79 101 строка, девять недель с 27.07.2026.
- `reports/training_summary.json`, `selection.json`, `validation.md` — обучение и выбор.
- `reports/comparison.json`, `reports/validation.md` — метрики активной модели.
- `reports/current_audit/` — историческая проверка предыдущего `log_zero` и исходных данных.
- `reports/docker_recovery/verification.json` — автономный Linux-тест предыдущей версии.
- `docs/REVIEW.md` — свежие проверки версии, взятой из GitHub.

В Git нет `hakaton.zip`, панелей, предсказаний фолдов и окружения. Для аудита из
сырых данных сначала нужен архив и `python -m forecast.cli prepare --archive hakaton.zip`.
Отсутствие локального кэша на свежем клоне ожидаемо.

## Перед изменением модели

1. Сохраните текущие `model/`, `outputs/submission.csv` и отчёт выбора в локальный
   каталог `experiments/`. Он исключён из Git и архива решения.
2. Задайте список кандидатов и способ выбора до просмотра их результатов.
3. Первые два окна начинаются 19.01 и 23.03.2026; третье — 25.05.2026. Третье уже
   подробно разобрано: при дальнейшей настройке нельзя объявлять его новым независимым тестом.
4. Проверьте все пять метрик ТЗ, общий знаковый bias и ошибки редких серий.
   Ранговый скор зависит от списка кандидатов и не равен месту в лидерборде.
5. Заменяйте рабочие артефакты только после подтверждённого улучшения. Сохраняйте
   конфигурацию, seed, версии, хеш данных и результаты в `reports/experiments.jsonl`.

Не используйте наблюдения после даты каждого среза, включая категории.
Запрошенный список пар фильтрует выдачу, но не удаляет контекст признаков.
Отрицательные остатки допустимы, продажи остатком не ограничиваются.
Обучение, CLI и API должны использовать общие преобразования из `forecast/`.

## Проверки

```sh
python -m pytest
python -m ruff check forecast app tests tools score.py
```

Для изменения контейнера повторите сборку и автономный тест из
[HUMAN_GUIDE.md](HUMAN_GUIDE.md#контейнер-без-сети). Проверяйте актуальность замеров,
а не только наличие прошлых отчётов. Не запускайте полное обучение ради правки документации.

После этапа обновите `HANDOFF.md`: результат, проверки, оставшиеся вопросы и
следующий шаг. Не записывайте в общие инструкции PID, расход личного аккаунта,
локальные пути пользователя и историю переписки. Публикация разрешена только
в текущий приватный репозиторий; остальные границы полномочий заданы в `AGENTS.md`.

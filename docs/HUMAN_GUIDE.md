# Участникам команды: что готово и как пользоваться

Проект прогнозирует недельные продажи товаров по складам на девять недель.
Здесь уже есть обученная модель и готовый конкурсный результат. Для получения
текущего submission заново обучать модель не нужно.

## 1. Забрать результат для конкурса

- Готовый файл: [outputs/submission.csv](../outputs/submission.csv).
- В нём 79 101 строка: 9 недель, 11 складов, 799 товаров.
- Недели: 27 июля — 21 сентября 2026 года.
- Колонки: `week,warehouse_name,article,quantity`.
- Модель использовала историю только по 26 июля 2026 года включительно.

На GitHub откройте файл и скачайте его исходное содержимое. Полный комплект кода,
модели и документации также можно скачать архивом репозитория или из раздела Releases,
если выпуск уже опубликован.

**Важное допущение:** организаторы не предоставили эталонный список пар «склад × товар».
Пока используется полное произведение 11 × 799. Если команда получит список,
сообщите агенту и передайте CSV с `warehouse_name,article`. Проверить соответствие
скрытому эталону заранее мы не можем.

Меньше — лучше. Это проверка на историческом окне, а не результат скрытого теста

Подробный отчёт: [validation.md](../reports/validation.md).

## 3. Запустить API без обучения

Нужны Git и Python 3.13. В PowerShell:

```powershell
git clone https://github.com/Va-Ya/sberhack-forecast.git
cd sberhack-forecast
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt -c constraints.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

На Linux после создания окружения используйте `.venv/bin/python` вместо
`.venv\Scripts\python.exe`. Дополнительные scikit-learn и pytest для инференса не нужны.

Откройте <http://127.0.0.1:8000/docs>. В `POST /predict` загрузите два CSV.
Для небольшой демонстрации в репозитории есть `data/demo_sales.csv` и
`data/demo_stock.csv`: это синтетический пример одной пары за 181 день.
Он вернёт 9 строк, а не полный конкурсный прогноз.

```powershell
curl.exe -X POST http://127.0.0.1:8000/predict -F "sales=@data/demo_sales.csv" -F "stock=@data/demo_stock.csv" -o demo_forecast.csv
curl.exe "http://127.0.0.1:8000/predict/all?format=csv" -o cached_forecast.csv
```

GET выдаёт последний успешный POST. До первого POST возвращается 409; после
перезапуска кэш пуст. Дата начала API-прогноза определяется по загруженным данным.
Отдельный конкурсный файл в `outputs/` остаётся результатом на полной истории.

Первые 100 исходных строк в `data/sample_*.csv` показывают схему. Они не содержат
180 дней истории и не подходят для успешного POST. Для демонстрации используйте `demo_*`.

## 4. Что ещё нужно сделать

1. Подтвердить список допустимых пар у организаторов, если такая возможность появится.
2. Проверить Docker на машине с рабочим Linux engine. На исходном компьютере
   запуск WSL остановился с таймаутом; администраторский перезапуск службы недоступен агенту.
3. После успешной сборки выполнить автономный smoke-тест с `--network none`.
4. Перед отправкой проверить сроки и требования организаторов к архиву кода.
5. Финальную загрузку и уведомление организаторов выполняет команда.

Команды Docker и точная диагностика: [environment.md](../reports/environment.md).
Контейнерная проверка пока **не пройдена**; наличие Dockerfile не заменяет её.

## 5. Передать работу другому человеку или агенту

Передайте ссылку на закрытый репозиторий и откройте ему доступ через владельца
репозитория. Учётные данные и ключи в чат или Git передавать не нужно.

Для человека достаточно этого файла, README и HANDOFF.
Для агента используйте [CONTINUE_PROMPT.md](../CONTINUE_PROMPT.md).

В Git включены код, модель, прогноз, маленькие примеры и отчёты. Исходный
`hakaton.zip`, виртуальное окружение и временные кэши не включены. Для переобучения
архив данных нужно отдельно положить в корень проекта. Его SHA-256 записан в
`reports/data_audit.json`.
